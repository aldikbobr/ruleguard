## 1. Суть

**Одна фраза:** RuleGuard показывает, действительно ли «одинаковые» рынки на Kalshi и Polymarket одинаковы по правилам расчёта, при каких сценариях они разойдутся и какой спред реален с учётом этого риска.

**Главный сдвиг относительно конкурентов:** они показывают *разницу в цене*, а мы — *разницу в цене с учётом риска разных правил* и объясняем, откуда он.

**Питч за 30 секунд:**
> «Сканеры показывают расхождение в 80 центов между Kalshi и Polymarket как лучшую возможность. На деле это часто разные контракты. Трейдер хеджировался на +$3 и потерял $47, потому что платформы по-разному рассчитывают рынок, если игрок не вышел. RuleGuard — слой эквивалентности для prediction markets. Для каждой пары он показывает, одинаковы ли правила, при каких сценариях рынки разойдутся и какой спред реален с учётом риска. Агрегаторы и боты подключают нас по API, а оценки хранятся в открытом реестре на Solana».

## 6. Как работает продукт

```
 Kalshi API ─┐                                   ┌─> Веб-страница (список пар, карточка пары)
 Polymarket ─┼─> [1] Сопоставление ─> [2] Паспорт ─> [3] Сравнение ─> [4] Итог ─┼─> REST API
 DFlow ──────┘       (кандидаты)       рынка (ИИ)     по полям        и сценарии  ├─> Telegram-уведомления
                                                                                └─> Реестр на Solana
```

### [1] Сопоставление
- Сначала попробовать готовое сопоставление из **pmxt** ⚠️ (качество не проверено).
- Своё сопоставление с «вето» (подход из статьи на dev.to):
  - **числа:** если в одном названии есть числа, наборы чисел должны совпадать (иначе «92–93°» склеится с «90–91°»);
  - **ключевые слова:** closest, margin, before, after, win, lose… должны быть в обоих названиях;
  - **география:** разные места означают, что это не пара.
- Скоринг: 0.4·Jaccard + 0.3·containment + 0.3·sequence ratio, жадное назначение один к одному.

### [2] Паспорт рынка (ИИ извлекает структуру из текста правил)
```json
{
  "venue": "kalshi | polymarket",
  "market_id": "…",
  "title": "…",
  "subject": "Federal Reserve",
  "event": "cuts target rate",
  "threshold": {"op": ">=", "value": 25, "unit": "bps"},
  "resolution_source": ["Federal Reserve press release"],
  "source_type": "named_official | named_media | consensus | oracle",
  "time_window": {"deadline": "2026-12-31T23:59:00", "timezone": "America/New_York"},
  "edge_cases": {
    "cancellation_or_postponement": "…",
    "participant_did_not_play": "…",
    "data_revision_after_expiry": "…",
    "no_data_available": "…"
  },
  "dispute_mechanism": "UMA oracle | venue internal",
  "rules_hash": "sha256 текста правил",
  "quotes": {"field_name": "точная цитата из правил"}
}
```
**Правило:** у каждого поля должна быть **точная цитата** из правил. Если цитаты нет, значение `unknown`, и ИИ его не додумывает.

### [3] Сравнение по полям
Для каждого поля: `same` / `minor_diff` / `material_diff` / `unknown`, с объяснением и цитатами обеих сторон.

### [4] Итог по паре
- **Класс:** `equivalent` / `equivalent_with_caveats` / `different` / `uncertain`
- **Сценарии расхождения:** «если X, то A рассчитается как…, B как…, ваша позиция YES на A и NO на B потеряет до …»
- **Спред:** показывать обычный спред с комиссиями **и** рядом класс риска. **Не выдумывать** «вероятность расхождения» числом, пока нет данных для такой калибровки.
- **Принцип: при сомнении выбирать осторожный ответ.** Лучше `uncertain`, чем ложное `equivalent`.

## 9. Проверка спроса (идёт параллельно, с первого дня)

### Каналы
- **Telegram-канал:** ежедневно 3–5 пар в формате «цена + разница в правилах + сценарий».
- **Трейдеры (15 человек):** r/Kalshi, r/Polymarket, Discord-сообщества, X.
- **Агрегаторы и боты (5 команд):** Capitola, команды с pmxt, получатели грантов DFlow.

### Шаблон сообщения агрегатору (EN)
> Hi! I'm building RuleGuard — a rule-equivalence layer for prediction markets. We parse Kalshi/Polymarket resolution rules clause-by-clause and flag pairs that look identical but settle differently (e.g. player-DNP, source, deadline). Quick question: when you route "the same event" across venues, how do you check the markets are actually equivalent today? Would a free API for that be useful to try?

### Вопросы трейдерам
Не спрашивать «нравится ли вам», а спрашивать про прошлое поведение:
1. Когда вы в последний раз торговали один и тот же рынок на двух площадках?
2. Как проверяли, что правила совпадают? Сколько времени это заняло?
3. Теряли ли деньги из-за разных правил? Сколько?
4. Чем пользуетесь сейчас? Платите ли за это?

### Пороги (ориентир, можно поправить)
- ✅ **Успех:** 30+ подписчиков канала, **2–3 команды-агрегатора** согласились попробовать API, 3+ трейдера описали реальный убыток из-за правил.
- ❓ **Неопределённо:** интерес есть, но нет ни одного «попробую» → изменить формулировку или сегмент.
- 🛑 **Стоп:** меньше 10 подписчиков, никто не описал реальный убыток, агрегаторы говорят «не нужно».

## 12. Риски и точки остановки

| Риск | Что делать |
|---|---|
| Polymarket не отдаёт правила через API | собирать с публичных страниц в рамках правил сайта или 🛑 пересмотреть идею |
| Существенных различий почти нет | 🛑 проблема редкая, вернуться к выбору ниши |
| ИИ ложно говорит `equivalent` | осторожный порог, `uncertain` по умолчанию, ручная проверка топовых пар, опубликованная точность |
| Агрегаторам это не нужно | сместиться на ботов и хеджеров |
| Конкурент добавит такую функцию | преимущество в данных (разметка и история правил) и глубине |
| Юридические риски | позиционироваться как информационный сервис, **не финансовый совет**. Не исполнять сделки за пользователей |
| Не хватает времени | резать шаг 8 (Solana-реестр), затем Telegram-бот. Исследование и точность не резать |
